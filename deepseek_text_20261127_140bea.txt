Crea la estructura completa del proyecto "propuesta_servicios" para el
Hackatón Venezuela INNOVA 2026. Stack obligatorio:
- Backend: FastAPI + Pydantic v2 + SQLAlchemy + SQLite + Uvicorn
- Frontend: Jinja2 + Tailwind CDN + Alpine.js CDN (sin build step)
- IA: SDK oficial `google-genai` (NO `google-generativeai`), modelo
  `gemini-3.8-flash`, con Google Search Grounding habilitado.
- Cifrado: AES-256-GCM con `cryptography.hazmat.primitives.ciphers`
  (NO usar `cryptography.fernet`, que es AES-128).

==============================================================
REGLA ARQUITECTÓNICA CRÍTICA
==============================================================
`evaluar_lote.py` DEBE funcionar de forma autónoma con solo `agent/`,
sin importar nada de `app/` ni de SQLite. Esta separación es requisito
del reto: los 25 puntos automáticos dependen del script de lote, no de
la web. El web app puede importar `agent/`, pero nunca al revés.

==============================================================
1. agent/schemas.py
==============================================================
- Item: descripcion, cantidad, unidad, precio_unitario, subtotal,
  evidencia (archivo, pagina, bbox, url, confianza)
- Clausula: texto, categoria (Enum: flete, seguro, traslado, garantia,
  recargo, exclusion, software_trial, penalidad, otro),
  impacto_estimado_usd (Optional[float]), evidencia
- PropuestaExtraida: archivo, fuente (Enum), proveedor,
  ubicacion_proveedor, items, clausulas, totales_declarados (subtotal,
  impuestos, total), moneda, confianza_global, anomalias_ingesta
- ResultadoAuditoria: propuesta, descartada (bool), motivos_descarte
  (list[str]), tco (TCO), technical_score (float), notas
- SalidaJSON EXACTO: reto="propuesta_servicios", repositorio (str),
  commit (str), inicio (ISO8601 con -04:00), fin (ISO8601 con -04:00),
  procesados (list[{archivo, hora ISO8601}]), ranking (list[str] sin
  duplicados, válidas primero mejor→peor, luego descartadas)

==============================================================
2. agent/extractor.py
==============================================================
- Usa `google-genai`:
  client.models.generate_content(
      model="gemini-3.8-flash",
      contents=[Part.from_bytes(data, mime_type), prompt],
      config=types.GenerateContentConfig(
          response_mime_type="application/json",
          response_schema=PropuestaExtraida,
          temperature=0.0,
      ),
  )
- Maneja PDF nativo, JPG/PNG (visión), XLSX (openpyxl, sin LLM).
- Extrae ítems, totales, cláusulas, notas al pie y texto sospechoso
  (posible prompt injection) TRANSCRITO LITERALMENTE, sin obedecerlo.
- Reintentos con backoff exponencial (3 intentos) ante error de API.
- Si un archivo falla tras reintentos, devuelve PropuestaExtraida con
  anomalias_ingesta marcando el fallo; NO lanza excepción al pipeline.

==============================================================
3. agent/validators/ (DETERMINÍSTICO PURO, SIN LLM)
==============================================================
- injection.py: lista de patrones regex (ES + EN) que detectan órdenes
  dirigidas a IA. Devuelve InjectionResult(detected, matches, score).
  Se ejecuta SIEMPRE antes de confiar en la extracción del LLM.
- arithmetic.py: tolerancia 0.01 USD. Verifica por ítem
  (cantidad*PU==subtotal) y suma (sum(subtotales)==subtotal declarado)
  y (subtotal+impuestos==total declarado). Si falla → descarte.
- scope.py: regla "11 equipos = 10 estudiantes + 1 docente + periféricos
  + UPS". Si la propuesta no cubre los 11 o falta UPS → descarte.
- compatibility.py: verifica socket CPU/placa, tipo RAM (DDR4/DDR5),
  longitud GPU vs gabinete, capacidad PSU ≥ consumo y UPS ≥ carga.
  Si hay incompatibilidad → descarte.

==============================================================
4. agent/market/search_grounding.py
==============================================================
- Usa Gemini con `types.Tool(google_search=types.GoogleSearch())`
  para investigar precio de cada componente clave.
- CACHÉ en disco (JSON) por (componente, fecha_dia) para que el
  ranking sea REPRODUCIBLE. Sin caché, dos corridas dan distinto.
- Devuelve PriceResearch: componente, rango_usd (p25, p75 o min, max),
  precios_encontrados (url, precio_usd, fecha_consulta), confianza.
- Si no hay ≥3 precios válidos, marca confianza < 0.6 y NO descarta
  por sobreprecio solo con este dato.

==============================================================
5. agent/tco.py y agent/ranker.py (DETERMINÍSTICO PURO)
==============================================================
- tco.py: base + flete (si "No incluye flete" y proveedor fuera de
  Caracas → 580 USD de referencia Maracaibo→Caracas) + recargos
  (si "recargo 50%" → base*0.5) + IVA (16% por defecto). Devuelve
  desglose paso a paso (lista de {concepto, monto}).
- ranker.py: válidas ordenadas por (-technical_score, tco.total,
  proposal.id); descartadas al final (alfabético). Sin duplicados.

==============================================================
6. agent/pipeline.py
==============================================================
- Orquesta: extractor → injection → arithmetic → scope →
  compatibility → market (con caché) → tco → ranker → salida.
- Procesa TODOS los archivos de `propuestas/` (no omite ninguno).
- Devuelve lista[ResultadoAuditoria] + ranking.
- No importa nada de `app/`.

==============================================================
7. evaluar_lote.py
==============================================================
- CLI con argparse: --input lote --output salida.json
- Estructura esperada: lote/proyecto.pdf y lote/propuestas/*.{pdf,jpg,png,xlsx}
- Obtiene commit con subprocess: git rev-parse HEAD
- Timestamps en America/Caracas con ISO 8601 (-04:00).
- Escribe salida.json con esquema EXACTO (reto, repositorio, commit,
  inicio, fin, procesados, ranking).
- Un archivo con error NO detiene el lote: se marca en `procesados` y
  se incluye en `ranking` como descartada.
- Al final imprime un resumen en consola.

==============================================================
8. app/main.py + templates/ (UI)
==============================================================
- /login con roles (Carga, Revisor, Aprobador, Solo lectura).
- /dashboard: lista proyectos, estados (Recepción, Evaluación,
  Revisión, Comité, Adjudicado), filtros.
- /project/{id} con pestañas:
  · Recepción: carga proyecto + 3–20 propuestas con semáforo de
    calidad de ingesta por archivo.
  · Evaluación: botón "Evaluar Propuestas de Servicios" + panel de
    trazabilidad EN VIVO usando SSE (/project/{id}/evaluate/stream).
  · Revisión: tabla comparativa (declarado vs. TCO real) + dictamen
    de descarte por propuesta con evidencia citada.
- /project/{id}/report: informe exportable a PDF (HTML print) y CSV.
- /project/{id}/chat: chat NL sobre los documentos del proyecto
  (RAG restringido, cita fuentes).
- Directorio de proveedores con alertas de descartes previos.
- Conversión de moneda con tasa BCV editable (campo + fecha + fuente
  para auditoría).
- Bitácora de revisión humana (quién, qué, cuándo) append-only.
- Cifrado AES-256-GCM de archivos en disco (app/crypto.py, usando
  cryptography.hazmat.primitives.ciphers.Cipher + modes.GCM).
